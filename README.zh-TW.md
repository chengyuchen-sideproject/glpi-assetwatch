# 資產監看 Asset Watch（GLPI 外掛）

[English](README.md) | 繁體中文

[![CI](https://github.com/chengyuchen-sideproject/glpi-assetwatch/actions/workflows/ci.yml/badge.svg)](https://github.com/chengyuchen-sideproject/glpi-assetwatch/actions/workflows/ci.yml)

GLPI 11 外掛（GLPI 10 請用 1.x 版）。它會看 **GLPI Agent** 回報的資料，伺服器出狀況時寄信給該機器的技術群組：

| 檢查項目 | 規則（預設值） | 寄信方式 |
|---|---|---|
| **沒回報** | 超過 36 小時沒收到回報（可依電腦類型調整） | 每小時彙整 |
| **硬碟空間不足** | 分割區剩餘空間 < 10% **而且** < 20 GB | 每小時彙整 |
| **硬體變動** | 記憶體總量、實體硬碟（依序號）、CPU 有增減 | 一個事件一封 |
| **身分變動** | 序號、主機名稱、實體網卡的 MAC 或 IP | 一個事件一封 |
| **機櫃位置變更** | 有人在 GLPI 把設備放進、移動或移出機櫃 | 一個事件一封，信中寫明是誰改的 |

「沒回報」和「硬碟」這類狀態型告警，**發生時寄一次**，持續中**每 3 天提醒一次**，**恢復時再寄一次**。
同一輪檢查的所有告警會依技術群組**合併成一封信**。所以交換器故障導致十台伺服器同時斷線時，只會收到一封信，而不是十封。
GLPI 11 一台設備可以有**多個技術群組**：每個群組各自收到一封彙整信（只列自己負責的機器），單次事件信（硬體、身分、機櫃）會寄給該設備的所有技術群組。

這個外掛只**讀取** GLPI 的資料，不會連到你的機器，也不會修改任何資產（2.3 手動填寫的接線存在外掛自己的資料表，並在設備的歷史紀錄留一行）。

2.2 起另有**機房盤點**頁（依機櫃列出每個機房的設備、即時狀態與到現場要確認的落差）和儀表板的**「機房」篩選**。
2.3 起再加上每個機房的**平面圖**、可列印的**機櫃 QR code 標籤**，以及**網路架構圖**（哪台設備接到哪台 switch）。

## 需求與相容版本

| | 支援範圍 | 實測版本 |
|---|---|---|
| GLPI | 11.0.x（`11.0.0` ~ `11.0.99`） | **11.0.13**（官方 `glpi/glpi` Docker 映像檔） |
| PHP | 8.2 以上（GLPI 11 的需求） | 8.2、8.3、8.4（單元測試）；8.5.12（端到端測試，映像檔內建） |
| 資料庫 | GLPI 11 支援的 MariaDB 10.6+ / MySQL 8.0+ | MariaDB 10.11 |
| 資產資料來源 | GLPI 原生 inventory（GLPI Agent） | GLPI Agent JSON 格式 |

| 版本 | GLPI | 分支 |
|---|---|---|
| **2.x** | 11.0.x | `main` |
| 1.x | 10.0.x | `1.x`（只修錯誤） |

判斷規則放在 `src/Core`，不依賴 GLPI，兩個版本共用。

GLPI 端還需要：

- **自動動作設成 CLI 模式**（官方 Docker 映像檔預設就是）。如果是 GLPI 模式，只有在有人瀏覽 GLPI 時才會執行檢查。
- **已啟用 E-mail 通知**，而且 SMTP 能正常寄信（設定 > 通知）。
- 電腦要設定**技術群組**（「負責硬體的群組」欄位，GLPI 11 可以選多個），群組成員要有 E-mail。設定頁會顯示有幾台受監看的電腦還沒設定。

## 安裝

```bash
# 在 GLPI 主機上，進入掛載到 /var/www/glpi/plugins 的目錄
cd glpi_plugins
git clone https://github.com/chengyuchen-sideproject/glpi-assetwatch.git assetwatch
```

資料夾**一定要叫 `assetwatch`**。接著到 GLPI 的 **設定 > 外掛程式 > Asset Watch**，按「安裝」再按「啟用」。也可以用命令列：

```bash
docker exec -u www-data glpi_app php bin/console plugin:install --username=glpi assetwatch
docker exec -u www-data glpi_app php bin/console plugin:activate assetwatch
```

命令列請用 `www-data` 身分執行。用 root 跑的話，會在 `/var/glpi/files/_cache` 留下 root 擁有的快取檔，網頁端之後就無法更新這些檔案。

### 離線安裝（無法連網的 Docker 主機）

這個外掛是純 PHP，不需要 Composer、沒有 `vendor/`，也不從 CDN 載入任何東西；翻譯檔（`.mo`）已經編譯好放在裡面。安裝和執行都不需要連網，只要把檔案帶進去就好。

1. 在能上網的電腦，從 [Releases](https://github.com/chengyuchen-sideproject/glpi-assetwatch/releases) 頁面下載 `assetwatch-<版本>.tar.gz` 和對應的 `.sha256` 檔。也可以從原始碼自己打包：`git archive --format=tar.gz --prefix=assetwatch/ -o assetwatch-2.3.0.tar.gz v2.3.0`。不建議用 GitHub 的「Download ZIP」，解開後資料夾會叫 `glpi-assetwatch-main`，必須自己改名。
2. 把兩個檔案帶到 GLPI 主機上，執行：

   ```bash
   sha256sum -c assetwatch-2.3.0.tar.gz.sha256
   tar -xzf assetwatch-2.3.0.tar.gz -C ./glpi_plugins     # 會建立 glpi_plugins/assetwatch
   chmod -R a+rX ./glpi_plugins/assetwatch                # 讓容器內的 www-data（uid 33）讀得到
   ```

   `./glpi_plugins` 是掛載到 `/var/www/glpi/plugins` 的主機目錄。如果沒有掛載，也可以用 `docker cp assetwatch glpi_app:/var/www/glpi/plugins/` 直接複製進容器，但容器一重建外掛就會消失。
3. 用上面的兩行命令列指令安裝並啟用，也可以在網頁介面操作。
4. 到 **設定 > 通知**，把 SMTP 指向內網的郵件伺服器。

**離線升級**：把新版壓縮檔解開覆蓋 `glpi_plugins/assetwatch`，再到 **設定 > 外掛程式** 按「更新」。資料庫裡的告警歷史會保留。

**GLPI 本身也還沒裝？** 映像檔也要一起帶進去：在能上網的電腦執行 `docker save glpi/glpi:11.0.13 mariadb:10.11 -o glpi-images.tar`，到離線主機執行 `docker load -i glpi-images.tar`。

### 安裝後

1. 到 **設定 > 外掛程式 > Asset Watch** 的設定頁，看「健康檢查」區塊有沒有警告，需要的話調整門檻。
2. 到 **管理 > 設定檔 >（設定檔）> 資產監看** 分頁，把「讀取」和「確認告警」權限開給要看告警的技術人員。Super-Admin 預設擁有全部權限。
3. 確認伺服器都有設定技術群組。

第一次執行時，只會把每台伺服器當下的硬體記成**比對基準**，不發告警；從下一次回報起才開始偵測變動。

## 使用方式

- **工具 > 資產監看**：告警列表，預設只顯示觸發中和已確認的告警。可以像 GLPI 其他列表一樣搜尋和匯出。
- **告警頁**：顯示詳細內容。可以按**確認告警**，並選填備註和「暫停提醒到哪天」。確認後就不再寄提醒信，但問題消失時仍會自動結案並寄出「已恢復」通知。
- **資產上的「資產告警」分頁**：顯示這台的告警歷史和目前的比對基準。電腦有這個分頁；網路設備、機箱、PDU 等可以放進機櫃的設備也有，但只會出現機櫃變更的告警。
- **信件內容與收件人**：到 **設定 > 通知** 調整名稱為 `Asset Watch - ...` 的通知。範本有英文和繁體中文兩版，收件人會依自己在 GLPI 設定的語言收到對應的版本。

### 儀表板（2.1 起）

安裝後會多一個 **「Asset Watch」儀表板**（**資產 > 儀表板**，左上下拉選單切換），也可以把下列卡片加到**任何**儀表板：按儀表板右上的「編輯」，在格子上按「+」新增卡片，群組選「資產監看」。卡片能自由拖拉、調整大小、換顏色、換圖表類型，或刪掉不要的。

| 卡片 | 圖表類型 | 內容 | 點下去 |
|---|---|---|---|
| 受監看的電腦 | 大數字 | GLPI Agent 回報的電腦總數（未刪除） | 電腦列表 |
| 離線電腦（沒回報） | 大數字 | 現在已超過「沒回報」門檻的電腦（依電腦類型門檻**即時計算**，不必等每小時的檢查） | 沒回報告警 |
| 硬碟空間不足的電腦 | 大數字 | 有進行中硬碟告警的電腦 | 硬碟告警 |
| 進行中的告警 | 大數字 | 觸發中＋已確認 | 告警列表 |
| 電腦狀態 | 摘要數字／圓餅／甜甜圈／長條… | 正常／離線／硬碟不足 | 對應列表 |
| 進行中告警（依類型） | 同上 | 沒回報、硬碟 | 對應列表 |
| 離線電腦清單 | 搜尋清單 | 哪幾台離線、多久沒回報、負責群組 | — |
| 變動事件（最近 30 天） | 長條／折線 | 每天的硬體、身分、機櫃變動數；卡片的「上限」= 顯示最近幾天 | — |
| 需要到現場確認的設備（盤點）（2.2） | 大數字 | 篩選的機房（或所有機房）中有落差的設備數 | 盤點頁 |

- 數字依目前選的**實體**計算；沒有「資產告警：讀取」權限的人看不到這些卡片（安裝時只把「Asset Watch」儀表板開給有這個權限的設定檔）。
- 「Asset Watch」儀表板只在第一次安裝時建立，之後你改過的版面不會被覆蓋。
- **篩選**（2.2 起）：卡片會跟著儀表板上適用於電腦的篩選條件變化，包括 GLPI 內建的「位置」、「技術群組」、「狀態」、「製造商」等，以及外掛提供的**「機房」**篩選（該機房機櫃上的設備，加上位置屬於該機房的電腦）。在儀表板工具列按篩選圖示加入；GLPI 自己的電腦、網路設備、PDU 等卡片也能用。設了篩選時，告警類卡片只計算電腦的告警。
- **需要到現場確認的設備**（2.2）：有落差的設備數（見下方「機房盤點」），依「機房」篩選或所有機房計算，點下去開盤點頁。已經存在的「Asset Watch」儀表板不會自動加這張卡片，請用「編輯」>「+」加入。

### 機房盤點（2.2 起）

**工具 > 機房盤點**：一頁看完一個機房實際有什麼，盤點或進機房前用。可以選單一機房、整個資料中心、所有機房，或「沒上機櫃也沒設位置的電腦」：

- **依機櫃列出，U 位由上往下**：放在該機房機櫃上的所有設備（電腦、網路設備、PDU、機箱、被動設備等），顯示類型、序號、型號、IP、最後回報、技術群組，以及硬體摘要（記憶體、CPU、硬碟數，取自外掛的比對基準）。
- 每台設備一個**狀態**：正常、硬碟空間不足、離線（沒回報門檻）、**疑似已下架**（超過 **30 天**沒回報，可調）、無 Agent（從沒回報過；PDU、被動設備本來就是這樣）。
- **「到現場要確認」清單**，列出落差：

| 落差 | 意思 |
|---|---|
| 在機櫃上但從沒回報 | 電腦放在機櫃上，GLPI Agent 卻從沒回報過 |
| 疑似已下架 | 最後回報超過門檻天數 |
| 沒上機櫃 | 位置屬於這個機房（含子位置）、有在回報，但沒放進任何機櫃的電腦 |
| 序號重複 | 另一筆同類型資產有相同序號 |
| 沒有技術群組 | 這台電腦的告警沒有人會收到 |
| IP 不在機房網段內 | 它的 IP 都不在這個機房設定的網段內（電腦、網路設備） |

- **匯出 CSV**（UTF-8 含 BOM，Excel 直接開不會亂碼）與**列印**（列印時隱藏 GLPI 選單）。
- 一個機房包含：**它的機櫃上的設備**，加上位置是機房位置（或其子位置）、有在回報但沒上機櫃的電腦（符合多個機房時取位置最深的那個）。要用後者，請在每個機房設定「位置」（資產 > 資料中心 > 機房）。
- 機房網段與「疑似已下架」天數：**設定 > 外掛 > Asset Watch** 的「機房盤點」區塊（一行一個網段，例如 `10.1.0.0/16`，IPv6 也可以；寫錯的會顯示出來並略過；空白＝不比對）。
- 權限和告警列表相同（資產告警：讀取），只顯示目前實體的機房、機櫃與設備。唯讀，不寄信。

### 機房平面圖與機櫃標籤（2.3 起）

- **機房平面圖**：從上往下看機房，機櫃畫在它在機房裡的位置（GLPI 機櫃欄位「Position in room」，中文介面顯示為「机房中的位置」），依**到現場要確認的台數**（預設）、**U 佔用率**或**耗電**（型號耗電加總 ÷ 機櫃最大功率）上色。顯示在盤點頁每個機房的機櫃清單上方，以及每個機房的「**機房平面圖**」分頁。點機櫃會跳到它的清單。平面圖只畫到最後一個機櫃再多一格；沒設位置的機櫃列在圖下方。門檻：U 佔用 70% / 90%、耗電 60% / 80%、待確認 1 / 3 台。
- **機櫃標籤**（每個機櫃和平面圖上的按鈕）：**每個機櫃一張 A4**，左邊是 U 位正面圖，右邊每台設備一個 **QR code**（掃了開 GLPI 的資產頁），可以貼在機櫃門上。用 100% 縮放並勾選「背景圖形」列印。設備高度取自型號的「Required units」（中文介面顯示為「需要數量」；沒設定的算 1U）。QR code 用的是 GLPI 網址（設定 > 一般 >「應用程式的URL」），手機要連得到；QR code 由 GLPI 內建的 `bacon/bacon-qr-code` 函式庫產生，不用另外裝套件。

### 網路架構圖（2.3 起）

**工具 > 網路架構圖**：選一個機房、整個資料中心或所有機房，看每台設備接到哪台網路設備：

- **架構圖**：每台網路設備一欄（標出機櫃與 U 位），接在它上面的設備排在下方，網路設備之間的連線畫在上方；方框顏色＝Asset Watch 狀態。下面是每台網路設備的表格（port、設備、機櫃 / U、設備網卡、狀態、來源），以及**沒有任何接線紀錄**的電腦與網路設備。
- 兩種來源會合併：**GLPI 連接埠**（GLPI 裡已連接的連接埠，例如 switch 做 SNMP 網路盤點時自動記錄，精確到 port），以及用「**編輯接線**」**手動填寫**的（選網路設備即可，switch port 與設備網卡可不填）。手動接線存在外掛自己的資料表 `glpi_plugin_assetwatch_uplinks`，每次新增 / 移除都會寫進該設備的歷史紀錄。編輯需要 GLPI 權限「網路設備：更新」。
- **同一個 port 重複**：同一台網路設備的同一個 port 記錄了不只一台設備時會列出來。
- **匯出 CSV**（每條接線一行，最後是沒有接線紀錄的設備）與**列印**。

### 自動動作

| 名稱 | 頻率 | 工作 |
|---|---|---|
| `AssetwatchChanges` | 5 分鐘 | 把新的回報和比對基準比較（硬體變動、身分變動） |
| `AssetwatchStatus` | 1 小時 | 檢查沒回報和硬碟空間，寄提醒和彙整信 |
| `AssetwatchPurge` | 1 天 | 清除超過 180 天的已結案告警和彙整紀錄 |

GLPI 沒有「inventory 匯入完成」的 hook，所以硬體和身分變動由 `AssetwatchChanges` 偵測，回報後 5 分鐘內會發出。GLPI 匯入 inventory 時包在資料庫 transaction 裡，不會讀到匯入到一半的資料。

## 外掛會改動 GLPI 的哪些東西（以及如何還原）

| 異動 | 安裝時 | 移除外掛時 |
|---|---|---|
| 資料表 `glpi_plugin_assetwatch_alerts`、`_snapshots`、`_digests`、`_uplinks`（2.3） | 建立 | 刪除 |
| 設定值（context 為 `plugin:assetwatch`） | 寫入預設值，不覆蓋已存在的值 | 刪除 |
| 權限 `plugin_assetwatch_alert`、`plugin_assetwatch_config` | 開給能修改 GLPI 設定的設定檔 | 刪除 |
| 3 個自動動作 | 建立 | 刪除 |
| 4 個通知 + 2 個信件範本（`Asset Watch - ...`） | 不存在時才建立（升級時保留你改過的內容） | 刪除，佇列中尚未寄出的信也一併刪除 |
| 列表預設欄位 | 尚未設定時才建立 | 刪除 |
| 「Asset Watch」儀表板（2.1） | 不存在時才建立 | 刪除；放在其他儀表板上的資產監看卡片也一併移除 |

**移除（Uninstall）** 會清掉上表所有東西，外掛的告警歷史也會一併刪除。如果需要保留，請先從列表匯出。外掛不會修改任何 GLPI 核心資料表或資產紀錄。**停用（Disable）** 則會保留所有資料。

## 開發

```bash
bash dev/up.sh          # 啟動 GLPI 11.0.13 + MariaDB 10.11 + Mailpit，並安裝外掛（compose 專案名稱 assetwatch-dev11）
bash dev/scenarios.sh   # 用模擬的 GLPI Agent 回報跑端到端情境測試
bash dev/scenarios.sh --keep   # 同上，但保留測試告警，方便到介面上查看
php phpunit.phar        # src/Core 的單元測試（PHPUnit 9.6）
docker compose -f dev/docker-compose.yml exec -T glpi php plugins/assetwatch/dev/check_signatures.php   # 覆寫的 GLPI 方法簽章是否相容
python tools/i18n.py extract|compile|check   # 翻譯檔
```

- GLPI：http://localhost:8080（帳密 glpi / glpi）；Mailpit（攔截測試信）：http://localhost:8025
- 送一筆模擬回報：`dev/fake_agent.py web01 --memory 16384 --disk /:102400:4096`
- 目錄結構：`src/Core` 是純判斷規則（有單元測試，不依賴 GLPI）；`inc/` 是和 GLPI 銜接的部分（hook、排程、通知、介面）；`templates/` 是 Twig 範本。
- 執行時沒有任何第三方相依；開發工具只需要 Python 3 標準函式庫。

## 搬遷注意事項

- **搬到另一套 GLPI**：把 `assetwatch` 資料夾複製到目標的 plugins 目錄再安裝即可。告警歷史存在資料庫裡，要跟著資料庫一起搬，複製外掛資料夾不會帶過去。
- **資料夾名稱**必須維持 `assetwatch`，GLPI 會用它推算資料表和類別名稱。
- **換行字元**：repo 用 `.gitattributes` 強制 LF。如果從 Windows 用其他方式複製檔案，請保持 LF。PHP 本身不在意換行，但 Git diff 會出現整檔差異。
- **Docker volume**：正式環境的 compose 中，外掛目錄是掛到 `/var/www/glpi/plugins` 的主機路徑。注意：官方映像檔把 GLPI 的設定、檔案和 log 放在 `/var/glpi`（`GLPI_CONFIG_DIR`、`GLPI_VAR_DIR`、`GLPI_LOG_DIR`），請確認這個路徑有掛到持久化的 volume。
- **時區**：門檻是用 GLPI 的時間計算。容器的 `TIMEZONE` 要和資料庫時區一致，否則「沒回報幾小時」會算偏。
- **從 1.x（GLPI 10）升級到 2.x（GLPI 11）**：先把 GLPI 升到 11，再把 `glpi_plugins/assetwatch` 換成 2.x 版，到 **設定 > 外掛程式** 按「更新」（或 `plugin:install --force` + `plugin:activate`）。升級程式會：
  - 把 1.x 存的 HTML 編碼文字（`&#38;` 等，GLPI 10 的慣例）解回原文，包括比對基準裡的值，所以升級後**不會**因為名稱、型號、掛載點含 `&` 而誤報變動（實測）；可以重複執行。
  - 告警列表補上「項目」欄（GLPI 11 不再自動顯示第一欄）。
  - 進行中的告警、確認狀態、歷史都保留。
- **GLPI 本身的已知限制（不是外掛問題）**：GLPI 10 存進資料庫的電腦序號 / 名稱如果含 `&`、`<`、`>`，升到 GLPI 11 後仍是編碼形式，GLPI Agent 下次回報時比對不到，會**新增一台重複的電腦**（實測；`diagnostic:check_html_encoding` 不處理這種資料）。升級前可先查：`SELECT id, name, serial FROM glpi_computers WHERE name LIKE '%&#%' OR serial LIKE '%&#%' OR uuid LIKE '%&#%';`
- **沒有 CLI cron**：還是能運作，但只有在有人瀏覽 GLPI 時才會執行檢查。
